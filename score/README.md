# 功能

按作品和来源版本，保存原始乐谱、识别工程、编辑主文件与发布成果，主要整理五线谱和吉他六线谱。

## 本地资料与公开边界

本目录是本地曲目工作区，公开 Git 仓库仅跟踪本文件。曲目目录中的原图、裁剪、结构化音符、预览、工程、导出、专用脚本与参数均由 `.gitignore` 排除。初始化和识别照常使用以下目录结构。

修订与恢复依赖仓库外私有备份，保留文件清单、SHA-256、工具版本与校订记录。不要把曲目资料强制加入公开提交。历史处理与推送检查见 [公开仓库维护](../doc/PUBLIC_REPOSITORY.md)。

明确指定的教学片段单独放在 [examples/](../examples/README.md)，按精确文件与哈希登记；不解除本目录的忽略规则，也不将整谱作为示例。

根据原始谱式选择识别、校对和排版方式。五线谱保留音高、时值、声部和演奏标记；六线谱保留弦位、品位、节奏、调弦、变调夹及演奏技法，并以六线谱作为编辑和发布形式。简谱、手写谱和其他记谱法须先评估样张，再确定处理方式。

## 本级模块职责

每个作品目录保存该作品的资料，不同来源或编配按版本分开管理。

| 目录 / 文件 | 职责 |
| --- | --- |
| 曲目 `README.md` | 作品信息、目录职责与版本入口 |
| `source/` | 原始来源，各版本 README 记录谱式、来源、页序与使用条件 |
| `audiveris/` | Audiveris 的派生输入、`.omr` 工程、日志与未校对 `.mxl` |
| `recognition/`（可选） | 其他识别工具的评估输入、原始结果与未校订预览，按版本、工具分组 |
| `notation/` | 当前 MuseScore 工作流的 `.mscz` 编辑主文件、工具版本、校订清单与发布记录 |
| `export/` | 经过校对、从同一编辑主文件导出的 MusicXML 与 PDF |

## 目录模型

```text
score/<work-slug>/
├── README.md
├── source/<edition-slug>/
│   ├── README.md
│   ├── page-001.png
│   └── page-002.jpg
├── audiveris/<edition-slug>/
│   ├── input.tiff
│   └── ...
├── recognition/<edition-slug>/<tool-slug>/  （可选）
│   ├── README.md
│   └── ...
├── notation/<edition-slug>/
│   ├── README.md
│   └── <edition-slug>.mscz
└── export/<edition-slug>/
    ├── <edition-slug>.musicxml
    └── <edition-slug>.pdf
```

这是单个作品、单个来源版本的示意结构。初始化命令只创建 `source/`、`audiveris/`、`notation/`、`export/` 及记录模板；`recognition/` 按评估需要创建。各识别工具的目录按实际使用保留，不要求每个版本都有全部工程和成果。

## 命名规则

- `<work-slug>` 使用小写 ASCII 字母、数字和连字符，优先包含作曲家与作品标识，例如 `chopin-nocturne-op9-no2`。
- `<edition-slug>` 使用相同字符规则，描述出版社、来源或编配，例如 `imslp-peters`；不同来源、编配分开建版本。
- `<tool-slug>` 使用相同字符规则，标识识别工具，例如 `pdf-to-gp5`；工具输出、派生输入与评估记录由对应结果目录的 README 说明。
- 图片使用 `page-001.png`、`page-002.jpg` 等三位连续页码，从 001 开始，允许 PNG、JPG、JPEG 混合，扩展名小写。同一页码不得出现两个文件。
- PDF 来源使用 `score.pdf`；单一版本选择 PDF 或逐页图片，二者不混放。页数超过 999 时先明确分册。
- 编辑工程与发布成果统一使用 `<edition-slug>` 基名；识别工作文件保留 Audiveris 实际生成的名称。
- 工具代码使用 Git 管理；曲目修订使用仓库外私有备份管理，全局命名原则见 [AGENTS.md](../AGENTS.md)。

## 主文件与追溯

原始文件内容保持不变。`.omr` 用于回到 Audiveris 识别阶段校正，GP5 等其他工具的初步输出保存在对应识别结果目录；`.mscz` 是当前 MuseScore 工作流中持续编辑与排版的主文件，MusicXML 是交换格式，PDF 是阅读与打印成果。

文件格式与显示谱式分别确认。保存为 MusicXML 或在 MuseScore 中编辑，不代表必须改为五线谱；六线谱的编辑工程和发布 PDF 应确认采用六线谱谱表，并核对弦位、品位、节奏及演奏设置。

导入编辑器后，以编辑主文件继续修改；若回到识别工具重新处理，重新导入会替换编辑起点，必须先在仓库外私有备份中保存当前资料，并明确处理已有排版修改。脚本拒绝覆盖现有工程和发布文件，不自动合并两个阶段的改动。

局部识别、工具评估和未校订预览保留在相应识别目录，不直接登记为整部作品的编辑主文件或发布成果。识别输出能打开、能播放或能导出 PDF，只能说明文件通路可用，仍需对照原谱确认内容与谱式。

主文件变化后应更新校订记录并重新导出，旧 PDF 不代表当前编辑内容。主文件、导出与记录在同一份私有备份中保存。`publish` 命令在本地生成文件，公开传播须另行确认授权；来源不明或未完成校对时，不应把输出登记为已发布。

## 操作入口

先确认谱式、页序、来源版本及目标版式，再选择处理入口：

| 对象 | 当前处理入口 |
| --- | --- |
| 印刷五线谱 | `.venv/bin/python scripts/score.py`；`recognize` 调用 Audiveris，后续导入 MuseScore 校订、排版和导出 |
| 吉他六线谱 | 使用 [PDF-to-GP5 裁行计划与导出](../tools/PDF-to-GP5/README.md)，人工提供谱行范围和元数据；尚未接入统一 `recognize` 命令 |
| 简谱、手写谱及其他记谱法 | 先评估样张与工具输出，再确定可编辑格式和校订方式 |

统一命令说明见 [脚本入口](../scripts/README.md)，五线谱的完整操作见 [乐谱数字化指南](../doc/SCORE_WORKFLOW.md)。六线谱的方法和限制见 [六线谱处理说明](../doc/TABLATURE_EVALUATION.md)，具体日志与问题清单保留在本地曲目目录中。

当前 Audiveris 入口将多页图片按页码打包为多页 TIFF，过大的页面仅在派生输入中缩小，再作为一本乐谱处理。同一作品含多个乐章时，仍可能生成多个 MXL。其他工具的多页、声部和乐章合并规则应在使用前确认，不能默认逐个输入图片就会合成完整作品。

## 大型文件

导入前检查原图、派生输入和识别工程的总体体积。可重建的派生输入应在确认工程可重开、来源和处理步骤已记录且私有备份完整后，再决定是否删除；根据实际增长安排本地存储与私有备份容量。
