# README 编写指南

README 用于让读者不依赖上下文快速判断目录职责、资料组织方式和操作流程。

## 基本原则

- 使用稳定、明确的业务名词，避免阶段性和模糊命名。
- 说明“这里放什么”和“这里不放什么”，减少分类歧义。
- 操作步骤应可以直接执行，不依赖隐含前提。
- 示例只展示结构，不虚构尚未存在的正式资料。
- 目录规则发生变化时，同步更新对应 README 和根目录索引。

## 内容要求

项目或目录级 README 通常应包含：

1. 标题和一句话职责说明。
2. 输入资料与产出成果。
3. 目录结构或文件组织方式。
4. 命名规则和允许的文件类型。
5. 基本工作流及必要的质量检查。
6. 与其他目录或文档的相对链接。

内容较少时只保留必要章节，不为满足模板制造空段落。

## 层级关系

- 根目录 `README.md` 负责项目入口、目录总览和跨目录流程。
- 一级目录 `README.md` 负责该目录的完整规则。
- 子目录出现独立、稳定的命名或工作流时，应拥有自己的 `README.md`。
- 上级 README 只概括下级职责，详细规则保留下级文档，避免重复维护。

## 链接与命名

- 仓库内引用使用相对路径链接。
- Markdown 文件名统一使用 `README.md`。
- 主题、曲目等业务标识使用小写 ASCII 单词和连字符。
- 展示标题可以使用中文，但机器读取的稳定标识不使用空格或阶段性词语。

## 更新时机

目录职责、文件格式、入口、配置、命名规则或操作流程发生变化时，文档修改应与相关文件修改放在同一次提交中。
