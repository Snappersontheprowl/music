# 六线谱处理与评估方法

- 状态：`active`
- 最后验证：`2026-11-06`
- 适用范围：本地吉他六线谱图片的识别、合并和草稿导出
- 单一事实来源：[工具入口](../tools/PDF-to-GP5/README.md)、[本地资料规范](../score/README.md)、[公开边界](PUBLIC_REPOSITORY.md)

## 当前能力

PDF-to-GP5 用于图片或 PDF 转 GP5；MuseScore 用于编辑、设置六线谱谱表并导出 MusicXML、MSCZ 与 PDF。项目固定上游提交和 Python 依赖，保留识别器原始报告、参数、输入哈希和逐小节事件。

本地实测曾出现完整页转换失败、裁行后可转换的情况。转换成功也可能有漏音、漏闷音、分组和节奏错误。裁行入口读取用户提供的本地计划；谱行位置、调弦和元数据仍需人工确认，尚未自动分析任意版面。

## 评估步骤

1. 登记六线谱页序、调弦、变调夹、速度、拍号与来源条件。
2. 对照原图选取少量小节，独立记录弦号、品位、节奏和同时发声关系；参考转录留在本地曲目目录。
3. 运行未修改的识别器，保留 GP5、报告、事件和失败信息；人工给定的元数据不计入自动识别成功项。
4. 比较符号、起音、时值、分组、闷音和演奏记号；明确节奏是从符号读取还是由间距估算。
5. 覆盖范围清楚后再合并多页；空白小节、仅含跨行延音的小节和反复结尾须人工核对。
6. 导出后重新导入编辑器，检查 TAB 谱表、各小节弦号/品位和 PDF 显示；文件可打开只表示格式通路通过。

## 草稿边界

通用脚本按印刷顺序合并，省略反复/结尾语义与识别器生成的音符、拍效果，保留基本音符、闷音和时值。延音品位按前面同弦音符统一；找不到前音时中止，交由人工确认。

Capo 以文字保留，播放不叠加变调夹移调，避免 GP5 导入后重写品位。泛音、弯音、击勾弦、滑音、跨行延音和渐慢需在编辑阶段恢复。具体曲目的人工调整证据保存在本地。

## 资料与验证

原图、裁剪、音符参考、事件、日志、工程和导出全部留在被 Git 忽略的 `score/`，进行仓库外私有备份。公开说明只保留方法、接口和一般限制，不附真实曲谱或其结构化转录。

2026-11-06 验证：通用合并逻辑通过原创合成音符检查；实际 MuseScore 导出 GP5、MusicXML、MSCZ 和 PDF 后，TAB 谱表与合成弦号/品位保持一致。这不代表任意真实谱面的识别质量。
