# Music

本仓库用于整理音乐学习资料，主要包括乐理学习笔记、曲式分析、乐谱来源文件和 Audiveris 数字化成果。

## 目录职责

| 目录 | 职责 |
| --- | --- |
| `score/` | 按曲目保存来源谱、Audiveris 工程和导出成果 |
| `theory/` | 保存乐理笔记、曲式分析、练习和配套资料 |
| `doc/` | 保存项目级文档规范与操作说明 |

协作规则见 [`AGENTS.md`](AGENTS.md)，待办事项见 [`TODO`](TODO)。

## 乐理学习流程

1. 在 `theory/` 下按主题建立笔记，记录概念、例子、练习和参考资料。
2. 需要结合具体作品时，在笔记中使用相对链接指向 `score/` 中对应的曲目目录。
3. 新增或修正结论时，同步更新笔记中的数据、谱例和参考来源。
4. 笔记达到多个文件的规模后，升级为主题目录，并在其中提供 `README.md` 作为索引。

## 乐谱整理流程

1. 在 `score/` 下为每部作品建立稳定的曲目标识目录。
2. 将原始扫描页或下载谱面放入 `source/`，保留来源和版权信息。
3. 将 Audiveris 工程及其工作文件放入 `audiveris/`。
4. 将经过校对的 MusicXML、MXL、MIDI 或 PDF 放入 `export/`。
5. 详细目录结构和命名要求见 [`score/README.md`](score/README.md)。

## 文件与版本

- 原始谱面只保留来源版本，不在原文件上做不可逆修改。
- 导出文件必须能够追溯到对应曲目、版本和 Audiveris 工程。
- 大文件进入仓库前先评估体积；需要时再启用 Git LFS，不在当前阶段预置。
- 文件名和目录名使用稳定业务语义，不使用 `new`、`final`、`tmp`、`test2`、`v2` 等阶段性名称。

## 文档维护

目录职责、文件格式、命名规则或工作流发生变化时，应在同一次修改中更新相关 README。README 的编写要求见 [`doc/README_GUIDE.md`](doc/README_GUIDE.md)。
